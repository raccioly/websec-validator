## Inspected precision cases

These three Actual patterns were inspected against pinned source and reproduced with inert synthetic input. The synthetic JavaScript/YAML was passed to Python extractors as text, never executed. This was a selected review, not exhaustive adjudication of the 70 Actual leads or 116 total leads.

1. **Archive error helpers misidentified as authentication decoders.** [Actual's error utility](https://github.com/actualbudget/actual/blob/f8ad7c0ebd76e09c3431ed085c4d336c907bbcd1/packages/desktop-client/src/util/error.ts#L13) formats ZIP errors; another branch calls `getUnsafeZipMeta` and `getUnsafeZipError`. User-facing strings such as `unauthorized` satisfy WebSec's file-wide auth-context pattern. The detector consequently emits two HIGH authentication-decoder leads even though these inspected calls concern archive metadata. A minimal function returning an unauthorized-message string reproduced the lead. A paired `decodeJwtPayloadUnsafe(token)` feeding a role decision also emits a lead and must remain visible. Actual JWT decoding without verification is a distinct risk, documented by [node-jsonwebtoken](https://github.com/auth0/node-jsonwebtoken#jwtdecodetoken--options).

2. **Local streams misidentified as HTTP file serving.** [The release-note checker](https://github.com/actualbudget/actual/blob/f8ad7c0ebd76e09c3431ed085c4d336c907bbcd1/packages/ci-actions/bin/release-notes-check.mjs#L23) pipes a local README to stdout and a workflow-summary file. [The filesystem adapter](https://github.com/actualbudget/actual/blob/f8ad7c0ebd76e09c3431ed085c4d336c907bbcd1/packages/loot-core/src/platform/server/fs/index.api.ts#L76) copies a read stream into a write stream. Neither inspected operation is a browser response. WebSec nevertheless emits HIGH `serve-no-nosniff` because `createReadStream` alone is treated as serving. A minimal local reader reproduces this; its paired `.pipe(res)` HTTP handler also emits the lead and must remain visible. Node's [filesystem API](https://nodejs.org/api/fs.html#fscreatereadstreampath-options) defines a read stream, not an HTTP response. Other Actual serving leads were not adjudicated by this check.

3. **Numeric issue identifier misidentified as injectable text.** [The pinned workflow](https://github.com/actualbudget/actual/blob/f8ad7c0ebd76e09c3431ed085c4d336c907bbcd1/.github/workflows/vrt-update-generate.yml#L293) writes `github.event.issue.number` to metadata in a shell step. WebSec reports HIGH script injection. Minimal issue-number and issue-title fixtures both reproduce HIGH, though the latter is the meaningful attack pair. [GitHub Security Lab](https://securitylab.github.com/resources/github-actions-untrusted-input/) distinguishes constrained identifiers from attacker-controlled titles, bodies and refs. [GitHub's secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use) explains using intermediate environment variables for untrusted input. Expressions mixing a number with untrusted text must remain review leads.

## Actionable WebSec backlog

- Scope unsafe-decoder evidence to actual calls and executable authentication decisions in the relevant function. Strings, comments and unrelated functions must not manufacture that relationship. Preserve uncertain real token-decoder paths as leads; do not blacklist ZIP helper names. Also avoid marking every guard in a decoder-containing file as unverified automatically.
- Require a concrete HTTP response relationship for the file-serving rule. Keep local file/object reads as inventory evidence without asserting browser delivery. Preserve `sendFile`, response-piped streams and supported returned-response cases; unknown cross-function flows need an explicit limitation, not a safety claim. Bind attachment/nosniff evidence to the actual response when changing this rule.
- Treat only exact documented numeric context expressions as constrained. Do not exempt a larger expression merely because it contains a numeric or SHA property; retain title/body/ref interpolation, mixed expressions and unknown fields. Add paired metamorphic cases for comments, renames and mixed safe/unsafe operations.
- Rerun Actual after freezing the detector, recording any intentional exclusions and source-cap losses. Report route support gaps independently of execution success. Broader framework coverage and remaining public leads need separate evidence-backed review.

The first three backlog items now have bounded implementations and ten paired regression tests in `tests/test_public_precision.py`, with independent review complete. They retain token-decoder/HTTP-response/text-injection positives, and reject unrelated literal/sibling-function/local-stream evidence and exact numeric-context false positives. A review correction also prevents nested unused headers and response-body objects from supplying response security headers. These are limited lexical checks: aliases, cross-function response flow and complete token dataflow remain unverified. Cookie/PII control scoping and briefing uncertainty wording were handled in a separate local regression batch; those fixes do not validate the public applications.
